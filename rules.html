权限规则

本页是系统的唯一规则来源：3 个角色 × 3 个文件 × 2 种操作，共 18 条组合。判定逻辑与页面展示分离，页面只负责把结果如实呈现出来。

角色权限矩阵

读 = read，导 = export

每一格显示该角色对该文件的 读取 / 导出 两项判定，共 18 条组合。

角色 \ 文件 F001 普通业务报告 F002 内部财务报告 F003 敏感工资表
employee普通员工 读 允许导 允许 读 拒绝导 审批 读 拒绝导 拒绝
finance财务人员 读 允许导 允许 读 允许导 允许 读 拒绝导 拒绝
admin管理员 读 允许导 允许 读 允许导 允许 读 允许导 允许
为什么 employee 读 F002 是 DENY，导出 F002 却是 PENDING_APPROVAL？ 因为系统为读取和导出设了两种不同策略：读取直接拒绝，导出进入审批流程。 但只要不是 ALLOW，文件操作就不能执行。

三种决策的含义

这是评审最常追问的一处
决策 含义 是否执行文件操作
ALLOW 权限检查通过 是，执行成功后记录实际结果
DENY 权限不足或规则不允许 否，在文件操作之前拦截
PENDING_APPROVAL 操作需要人工审批 否，审批完成前不得执行

判定接口约定

A 侧函数 / B 侧接口 
# policy.py —— 权限判断函数（由 A 负责实现）
def check_permission(user_role, file_id, action):
    # user_role: employee | finance | admin
    # file_id:   F001 | F002 | F003
    # action:    read | export
    return {
        "decision": "ALLOW",             # ALLOW | DENY | PENDING_APPROVAL
        "reason":   "该角色对该文件有读取权限",
    }
前端页面只消费这个返回结构，不参与规则判断。
// POST /api/access —— 统一访问入口（由 B 负责实现）
{
  "user_role": "employee",
  "file_id":   "F002",
  "action":    "read"
}

// 返回
{
  "request_id": "REQ20261012103025",
  "decision":   "DENY",
  "reason":     "普通员工无权访问内部财务报告",
  "executed":   false          // 必须反映真实执行情况
}

额外安全规则

  1. 未知用户角色、未知文件编号、未知操作类型不得默认放行。
  2. 文件不存在时，应安全报错，不得执行读取或导出。
  3. 权限判断与实际文件操作必须分离。
  4. 所有受保护操作必须经过后端统一入口。
  5. 不能只在网页上显示"拒绝"，而实际仍然读取或导出文件。
